# Handoff — Indeed Key Code Parser

## What this project is

Android app + Rust server that reads the user's **own** OTP codes (with the
account/token label) from the **Indeed Key** app (`com.indeedid.key`) screen on
their own Android device, and forwards each code to a self-hosted webhook that
stores them.

- Scope: user's own codes, on the user's own device. Legitimate personal
  automation — NOT a covert/exfiltration tool. Enabling the reader requires an
  explicit, user-performed Android Accessibility opt-in.
- Reading mechanism chosen: **AccessibilityService** reads the code as text from
  the Indeed Key UI tree ("path 1", no OCR). Fallback if that fails: MediaProjection + OCR.

## Payload contract (binding)

```json
{ "account": "<name>", "code": "<6-8 digits>", "timestamp": "<RFC3339>", "source": "com.indeedid.key" }
```
Auth on every server endpoint: `Authorization: Bearer <secret>`.
Code validation: 6–8 ASCII digits, spaces stripped before validation.

## What still needs doing (the new agent's job)

Requires a shell (run OUTSIDE auto-mode, or a fresh session) and `sudo` for installs.

1. **Install tools (Arch Linux, needs sudo/user password):**
   ```bash
   sudo pacman -S --needed rust android-tools jdk17-openjdk gradle
   # Android SDK — pick one:
   yay -S android-studio            # GUI, bundles SDK
   # or headless:
   yay -S android-sdk-cmdline-tools-latest
   sdkmanager "platform-tools" "platforms;android-34" "build-tools;34.0.0"
   ```

2. **Point Gradle at the SDK:**
   ```bash
   echo "sdk.dir=$HOME/Android/Sdk" > android/local.properties   # adjust path
   ```

3. **Generate the Gradle wrapper** (the wrapper jar + `gradlew` + a re-created
   `gradle/wrapper/gradle-wrapper.properties` are missing — one file write was
   blocked last session):
   ```bash
   cd android && gradle wrapper --gradle-version 8.7
   ```

4. **Build & test the server:**
   ```bash
   cd server && WEBHOOK_SECRET=test cargo test
   ```
   Fix any compile errors from real toolchain feedback (code was never compiled).

5. **Build & test the app:**
   ```bash
   cd android && ./gradlew :app:testDebugUnitTest && ./gradlew :app:assembleDebug
   ```
   Note: `PayloadTest` needs `org.json` in unit tests — already added as
   `testImplementation("org.json:json:20240303")` in `app/build.gradle.kts`.

6. **Commit** (this repo's owner uses a personal commit format — no
   Co-Authored-By / no "Generated with" trailers; if a `git-commit` skill is
   available, use it):
   ```bash
   git add -A && git commit -m "feat: indeed key code parser — rust webhook + android reader"
   ```

7. **SPIKE (Task 0) — the real gate. A phone will be connected via USB (USB
   debugging on).** Verify Indeed Key exposes the code via accessibility:
   ```bash
   adb devices                       # confirm device (not 'unauthorized')
   # open Indeed Key on the phone showing a code, then:
   adb shell uiautomator dump /sdcard/win.xml && adb pull /sdcard/win.xml
   ```
   Inspect `win.xml`: is the 6–8 digit **code** present as a node `text`? Is the
   **account label** a nearby node, and how is it related (same parent/row)? If
   the code is blank / not present (e.g. `FLAG_SECURE`), path 1 fails → switch to
   path 2 (OCR); STOP and tell the user. If present, the tree structure may
   require tuning `extractEntry` (in `parse/CodeExtractor.kt`) + its unit tests to
   match the real container layout. Record findings in
   `docs/superpowers/notes/2026-08-31-spike-accessibility.md`.

8. **End-to-end (Task 10):** run the server, install the APK
   (`adb install android/app/build/outputs/apk/debug/app-debug.apk`), open the
   app's settings, set webhook URL (reachable from phone, e.g.
   `http://<host-ip>:8080/webhook`) + secret, tap Save, enable the accessibility
   service, open Indeed Key, then:
   ```bash
   curl -s -H "Authorization: Bearer <secret>" http://localhost:8080/codes
   ```
   Expect the account + code to appear. Record results in
   `docs/superpowers/notes/2026-08-31-e2e-verification.md`.
